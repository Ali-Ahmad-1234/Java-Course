Добро пожаловать на первую лекцию курса «Современные технологии программирования». Сегодня мы познакомимся с языком Java — одним из самых распространённых языков в мире, на котором пишут мобильные приложения (Android), веб-сервисы, корпоративные системы и многое другое.

## Часть 1. Что такое Java и в чём её особенность

### Java — объектно-ориентированный язык

Представьте, что вы собираете конструкцию из деталей конструктора: каждая деталь — это отдельный объект со своими характеристиками (форма, цвет, размер). В Java весь код строится вокруг таких «деталей» — классов и объектов.

В отличие от некоторых языков (например, C++), где допустим код вне классов, в Java любой фрагмент кода обязан находиться внутри класса. Даже простейшая программа «Hello World» требует объявления класса. Для маленьких примеров это может казаться излишним, но в больших проектах такая дисциплина помогает поддерживать порядок.

### Java — платформенно-независимый язык

Это одна из ключевых особенностей Java. Разберём, что стоит за этим утверждением.

Когда программа пишется на C или C++, компилятор превращает исходный код в машинный код — набор инструкций конкретного процессора. Проблема в том, что процессоры разных архитектур (Intel, AMD, ARM) понимают разные наборы команд, поэтому программа, собранная под Windows, не запустится на macOS или Linux без пересборки.

Java устроена иначе. Компилятор Java превращает код не в машинные инструкции, а в байт-код — промежуточный формат. Байт-код выполняется не напрямую процессором, а специальной программой — виртуальной машиной Java (JVM).

JVM существует для всех распространённых операционных систем. Ключевой момент: один и тот же байт-код запускается на любой JVM. Скомпилировав программу один раз, вы можете запускать её везде, где установлена JVM.

Отсюда девиз Java: «Write once — run anywhere» («Напиши один раз — запускай везде»).

Любопытный факт: название «Java» происходит от сорта кофе с острова Ява, поэтому логотип языка — чашка кофе. Язык создан Джеймсом Гослингом в компании Sun Microsystems в 1995 году — изначально для интерактивного телевидения.

### Путь от исходного кода до запуска

**Шаг 1. Написание кода.** Создаётся файл с расширением `.java`, например `Main.java`.

**Шаг 2. Компиляция.** Компилятор `javac` проверяет код на ошибки и создаёт файл `.class`, содержащий байт-код.

**Шаг 3. Запуск.** Команда `java Main` запускает JVM, которая читает `Main.class`, интерпретирует байт-код и выполняет программу.

Сравнение с C/C++:

| | C/C++ | Java |
|---|---|---|
| Компиляция | Исходный код → машинный код (.exe, .out) | Исходный код → байт-код (.class) |
| Результат | Инструкции конкретного процессора | Универсальные инструкции для JVM |
| Переносимость | Требуется пересборка под каждую платформу | Один .class-файл работает везде |
| Запуск | Напрямую операционной системой | Через установленную JVM |

## Часть 2. Первая программа — Hello World

Начнём с классической программы, выводящей «Hello World», и разберём её построчно.

```java
package lecture.one.hello;

public class Main {

    public static void main(String[] args) {
        System.out.println("Hello world!");
    }
}
```

### Разбор `package`

```java
package lecture.one.hello;
```

Пакет — это своего рода папка для классов. Чтобы избежать беспорядка, связанные классы группируют по пакетам, как вещи раскладывают по полкам шкафа. Имя пакета `lecture.one.hello` означает, что файл физически находится в каталоге `lecture/one/hello/`.

### Разбор `public class Main`

```java
public class Main {
```

- `public` — модификатор доступа: класс доступен отовсюду;
- `class` — ключевое слово объявления класса;
- `Main` — имя класса. Важное правило: имя файла должно совпадать с именем публичного класса.

### Разбор метода `main`

```java
public static void main(String[] args) {
```

Это точка входа в программу — именно с этого метода JVM начинает выполнение.

- `public` — метод доступен извне, JVM должна иметь к нему доступ;
- `static` — метод принадлежит классу, а не объекту;
- `void` — метод ничего не возвращает;
- `main` — обязательное имя метода;
- `String[] args` — массив аргументов командной строки.

### Разбор `System.out.println()`

```java
System.out.println("Hello world!");
```

- `System` — встроенный класс, предоставляющий доступ к системным ресурсам;
- `out` — объект стандартного потока вывода;
- `println` — выводит текст и переходит на новую строку (есть и `print()` — без перехода).

### Попробуйте в jshell

`jshell` — интерактивная консоль Java (входит в JDK с версии 9), позволяющая писать код и сразу видеть результат.

```
jshell> System.out.println("Привет, мир!")
jshell> String name = "Студент"
jshell> System.out.println("Привет, " + name + "!")
```

## Часть 3. Архитектура Java — JDK, JRE, JVM

Разберём три аббревиатуры, которые постоянно встречаются в Java-разработке. Их проще всего представить как три вложенные «матрёшки».

### JVM — виртуальная машина Java

Самая маленькая «матрёшка» — программа, выполняющая байт-код. Можно представить её переводчиком, объясняющим процессору, что делать.

Функции JVM:

- чтение и выполнение байт-кода (файлы `.class`);
- управление памятью программы;
- автоматическое удаление ненужных объектов (сборка мусора);
- обеспечение безопасности выполнения.

JVM ничего не знает о самом языке Java — она понимает только байт-код. Поэтому в байт-код JVM компилируются и другие языки: Kotlin, Scala, Groovy.

### JRE — среда выполнения Java

Средняя «матрёшка»: JVM плюс стандартные библиотеки классов (`String`, `ArrayList`, `File` и тысячи других). JRE нужен тем, кто хочет запускать готовые Java-программы, но не разрабатывает их.

### JDK — набор инструментов разработчика

Самая большая «матрёшка»: JRE плюс инструменты разработки:

- `javac` — компилятор;
- `java` — запуск программ;
- `javadoc` — генерация документации;
- `jar` — упаковка классов в архивы;
- `jdb` — отладчик;
- `jshell` — интерактивная консоль (с Java 9).

**Простое правило:** хотите запускать программы — ставьте JRE; хотите их писать — ставьте JDK (он включает JRE).

## Часть 5. Архитектура JVM изнутри

JVM состоит из трёх подсистем:

1. **Class Loader Subsystem** — загружает классы в память;
2. **Runtime Data Areas** — области памяти;
3. **Execution Engine** — выполняет байт-код.

### 5.1 Class Loader

Классы загружаются не все сразу, а по мере необходимости. Загрузка класса проходит три этапа.

**Этап 1: Loading.** Class Loader находит `.class`-файл, читает его и создаёт объект `Class` в памяти.

**Этап 2: Linking**, состоящий из трёх подэтапов:

- *Verification* — проверка корректности и безопасности байт-кода;
- *Preparation* — выделение памяти под статические переменные и присвоение значений по умолчанию;
- *Resolution* — замена символических ссылок на прямые.

**Этап 3: Initialization.** Выполняются статические блоки, присваиваются начальные значения статическим переменным.

### Иерархия загрузчиков классов

**Bootstrap Class Loader** — корневой загрузчик. Загружает базовые классы (`String`, `Object`, `System` и другие из `java.lang`, `java.util`, `java.io`). Написан на C/C++, поэтому:

```java
String.class.getClassLoader()  // вернёт null
```

**Platform Class Loader** — загружает классы платформы, не входящие в базовый модуль (XML, SQL и т.д.). До Java 9 назывался Extension Class Loader.

**Application Class Loader** — загружает классы вашего собственного приложения.

**Пользовательские загрузчики** — можно создать самостоятельно, например, для загрузки из зашифрованных файлов, из сети или для изоляции плагинов.

### Модель делегирования

Загрузчики работают по принципу «снизу вверх»: сначала запрос передаётся самому старшему загрузчику, и только если он не находит класс, поиск спускается ниже.

```
Application ClassLoader
        ↓ делегирует
Platform ClassLoader
        ↓ делегирует
Bootstrap ClassLoader
        ↓ не нашёл, возвращает
Platform ClassLoader
        ↓ не нашёл, возвращает
Application ClassLoader
        ↓ нашёл в classpath!
        → загружает класс
```

Почему это важно:

- **Безопасность** — нельзя подменить системные классы;
- **Уникальность** — каждый класс загружается только одним загрузчиком;
- **Видимость** — классы родительского загрузчика видны дочерним, но не наоборот.

### Пример собственного Class Loader

```java
package lecture.one.classloader;

public class MyLoader extends ClassLoader {

    private final String classesDir;

    public MyLoader(String classesDir) {
        this.classesDir = classesDir;
    }

    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        try {
            String path = classesDir + "/" + name.replace('.', '/') + ".class";
            byte[] classBytes = java.nio.file.Files.readAllBytes(java.nio.file.Paths.get(path));
            return defineClass(name, classBytes, 0, classBytes.length);
        } catch (java.io.IOException e) {
            throw new ClassNotFoundException("Не удалось загрузить класс: " + name, e);
        }
    }
}
```

### 5.2 Runtime Data Areas

**Heap (Куча)** — общая область памяти для всех объектов (`new ArrayList()`, строки, массивы). Доступна всем потокам.

**Stack (Стек)** — у каждого потока свой стек с локальными переменными, параметрами методов и адресами возврата. При вызове метода создаётся новый фрейм; по завершении он удаляется.

**PC Register** — счётчик команд, указывающий на текущую выполняемую инструкцию каждого потока.

**Method Area / Metaspace** — хранит структуру классов: методы, поля, константы. До Java 8 называлась PermGen с фиксированным размером (частая причина `OutOfMemoryError: PermGen space`). С Java 8 заменена на Metaspace, растущую по мере необходимости и не ограниченную параметром `-Xmx`.

**Native Method Stack** — стек для выполнения нативного кода (C/C++).

### 5.3 Execution Engine

**Interpreter** — читает и выполняет байт-код инструкция за инструкцией. Просто, но медленно при повторных вызовах.

**JIT Compiler** — находит «горячие точки» (часто выполняемый код) и компилирует их в настоящий машинный код, который затем выполняется напрямую процессором. Отсюда название HotSpot JVM.

**Garbage Collector** — автоматически находит объекты, на которые больше нет ссылок, и освобождает занятую ими память. Преимущества: нет утечек из-за забытого `delete`, нет обращений к уже удалённой памяти, программист сосредоточен на логике, а не на управлении памятью.

## Часть 6. Java Native Interface (JNI)

Иногда требуется код, написанный на других языках. Для этого существует JNI — Java Native Interface.

### Зачем нужен JNI

- доступ к системным функциям ОС;
- использование существующих библиотек на C/C++;
- работа с оборудованием;
- фрагменты кода, критичные к производительности.

### Как это работает

Метод объявляется в Java с ключевым словом `native`, а реализуется на C/C++.

**Шаг 1. Java-класс с native-методом:**

```java
package lecture.one.jninative;

public class NativeGreeting {
    static {
        System.load("C:/path/to/NativeGreeting.dll");
    }

    public native void sayHello();

    public static void main(String[] args) {
        new NativeGreeting().sayHello();
    }
}
```

**Шаг 2. Генерация заголовочного файла:**

```
javac -h . lecture/one/jninative/NativeGreeting.java
```

**Шаг 3. Реализация на C:**

```c
#include <jni.h>
#include <stdio.h>
#include "lecture_one_jninative_NativeGreeting.h"

JNIEXPORT void JNICALL Java_lecture_one_jninative_NativeGreeting_sayHello
  (JNIEnv *env, jobject obj) {
    printf("Привет из нативной библиотеки!\n");
}
```

**Шаг 4. Компиляция в библиотеку** (пример для Linux):

```
gcc -shared -fPIC \
    -I"$JAVA_HOME/include" -I"$JAVA_HOME/include/linux" \
    -o libNativeGreeting.so lecture_one_jninative_NativeGreeting.c
```

**Шаг 5. Запуск:**

```
java -Djava.library.path=. lecture.one.jninative.NativeGreeting
```

### Когда не стоит использовать JNI

- если задачу можно решить на чистой Java — используйте Java;
- JNI сложен в отладке и подвержен ошибкам (утечки памяти, краши JVM);
- нативный код не переносим между платформами.

Современная альтернатива — Foreign Function & Memory API (Project Panama, JEP 454), упрощающий работу с нативным кодом без C-обёрток.

## Часть 7. Типы данных в Java

Все данные в Java типизированы. Типы делятся на примитивные и ссылочные.

### Примитивные против ссылочных

**Примитивные типы** хранят значение напрямую: `int x = 5` — переменная содержит число 5.

**Ссылочные типы** хранят адрес объекта в памяти: `String s = "Hello"` — переменная содержит адрес, где хранится строка.

| Критерий | Примитивные | Ссылочные |
|---|---|---|
| Что хранят | Само значение | Адрес объекта |
| Где хранятся | В стеке | Объект в куче, ссылка в стеке |
| Значение по умолчанию | 0, false, `\u0000` | null |
| Сравнение `==` | Сравнивает значения | Сравнивает адреса |
| Может быть null | Нет | Да |

Частая ошибка новичков:

```java
String s1 = new String("Hello");
String s2 = new String("Hello");

System.out.println(s1 == s2);      // false — разные объекты
System.out.println(s1.equals(s2)); // true — содержимое одинаковое
```

Но есть нюанс — String Pool:

```java
String s3 = "Hello";
String s4 = "Hello";
System.out.println(s3 == s4);  // true — оба указывают на объект в String Pool

String s5 = new String("Hello");
String s6 = new String("Hello");
System.out.println(s5 == s6);  // false — разные объекты в куче
```

Java переиспользует одинаковые строковые литералы для экономии памяти, но это работает только для литералов — `new` всегда создаёт новый объект.

### Примитивные типы

| Тип | Размер | Диапазон | По умолчанию |
|---|---|---|---|
| byte | 8 бит | -128..127 | 0 |
| short | 16 бит | -32 768..32 767 | 0 |
| int | 32 бита | ≈ ±2.1 млрд | 0 |
| long | 64 бита | очень большое | 0L |
| float | 32 бита | ~6-7 значащих цифр | 0.0f |
| double | 64 бита | ~15 значащих цифр | 0.0 |
| char | 16 бит | символы Unicode | `\u0000` |
| boolean | — | true/false | false |

Точность дробных чисел:

```java
System.out.println(0.1 + 0.2);         // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);  // false
```

Для финансовых расчётов используйте `BigDecimal`.

Переполнение:

```java
byte b = 127;
b++;             // станет -128, а не 128!

int max = Integer.MAX_VALUE;
max + 1;         // станет Integer.MIN_VALUE
```

Java не бросает исключение при переполнении — программа продолжит работу с некорректным значением.

### Системы счисления и суффиксы

```java
int million = 1_000_000;         // подчёркивания для читаемости (Java 7+)

int decimal = 100;               // десятичная
int hex = 0x64;                  // шестнадцатеричная
int octal = 0144;                // восьмеричная
int binary = 0b01100100;         // двоичная

long bigNumber = 123456789L;     // L обязателен для long
float pi = 3.14f;                // f обязателен для float
double e = 2.71828;              // d необязателен для double
```

### Ссылочные типы

К ним относятся классы (`String`, `ArrayList`, ваши классы), интерфейсы (`List`, `Runnable`), массивы (`int[]`, `String[]`), перечисления (`enum`), аннотации (`@Override`).

### Попробуйте в jshell

```
jshell> int max = Integer.MAX_VALUE
jshell> max + 1
jshell> byte b = 127; b++; b
jshell> 0.1 + 0.2
jshell> 0.1 + 0.2 == 0.3
```

## Часть 8. Операторы в Java

### Арифметические

| Оператор | Название | Пример | Результат |
|---|---|---|---|
| `+` | Сложение | `12 + 5` | 17 |
| `-` | Вычитание | `12 - 5` | 7 |
| `*` | Умножение | `12 * 5` | 60 |
| `/` | Деление | `12 / 5` | 2 (целочисленное!) |
| `%` | Остаток | `12 % 5` | 2 |

При делении двух целых чисел результат тоже целый — дробная часть отбрасывается, а не округляется. Для дробного результата приведите хотя бы один операнд к `double`.

### Сравнения

| Оператор | Название |
|---|---|
| `==` | Равно |
| `!=` | Не равно |
| `>` | Больше |
| `<` | Меньше |
| `>=` | Больше или равно |
| `<=` | Меньше или равно |

### Логические

| Оператор | Название | Пример |
|---|---|---|
| `&&` | И | `true && false → false` |
| `\|\|` | ИЛИ | `true \|\| false → true` |
| `!` | НЕ | `!true → false` |

Короткое замыкание: если результат ясен по первому операнду, второй не вычисляется.

